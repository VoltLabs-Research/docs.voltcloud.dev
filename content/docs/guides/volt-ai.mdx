title: VOLT AI
description: Chat with an assistant that looks up your team's data, runs pipelines and drives the viewer, on a model your team configures.

VOLT AI is a chat assistant built into VOLT. It answers questions about your team's trajectories, analyses, plugins, clusters, notebooks and whiteboards by reading them through tools, so its answers come from your data rather than from guesses. It can also act: run an analysis pipeline, rename or delete things, draw on a whiteboard, open a trajectory in the 3D viewer and change what the viewer shows.

VOLT does not ship a model. VOLT AI runs on a model from a provider your team connects, with your team's API key.

## Connect a provider

Providers are set per team, in **Settings** › **Integrations** (`/dashboard/settings/integrations`), under **AI Providers**.

<Steps>
<Step>
Click **Connect**. The **Add provider** dialog opens.
</Step>
<Step>
Pick the **Provider** and enter its **API key**. Ollama needs no key; it asks for an **Endpoint** instead (`http://localhost:11434/v1` by default). For the other providers, **Custom endpoint (optional)** sends requests to a gateway of your own instead of the provider's API.
</Step>
<Step>
Under **Models**, add each model the team may use: its **Model ID** as the provider names it (for example `gpt-4o`) and an optional **Display name**, then **Add**. VOLT has no built-in model list, so only the models you add here are offered.
</Step>
<Step>
Choose the **Default model**, leave **Enabled** on, and click **Save**.
</Step>
</Steps>

A team has at most one integration per provider. Each one in the list has **Configure** and **Remove** buttons. To keep the current key when you configure a provider again, leave **API key** empty. The server stores keys encrypted and never sends them back to the browser.

| Provider | Provider |
|---|---|
| OpenAI | Cohere |
| Anthropic | DeepSeek |
| Google | DeepInfra |
| Groq | Cerebras |
| xAI (Grok) | Together AI |
| Mistral | Fireworks AI |
| Ollama | |

VOLT does not test the key when you save it. A wrong key shows up as a failed answer in the chat.

Managing providers uses the team's `team` permission: `team:read` to see them, `team:create` to connect one, `team:update` to change one and `team:delete` to remove one. With the built-in roles, only the **Owner** can change providers.

## Chat with VOLT AI

### The AI page

Open **VOLT AI** in the sidebar (`/dashboard/ai`). The sidebar switches to your conversations in the selected team: **New conversation**, a **Search…** field and the **Recent** list. Hover a conversation to rename it or delete it (**Delete this conversation?**). Conversations are private: only you see yours, and each belongs to the team it was started in.

<Screenshot name="volt-ai" alt="A VOLT AI conversation that ran an analysis pipeline after approval and answered with a table, open as a spreadsheet at the right" />

Type in **Ask anything** and press Enter to send. Next to the box, the model picker lists every model of the team's enabled providers, with the provider under each name. A conversation remembers the model you last used in it. When you haven't picked one, it uses the default model of the most recently connected provider. While VOLT AI answers, the send button becomes a stop button (**Stop generating**).

The answer streams in. Above the text, a collapsible trace shows the model's reasoning (**Thinking…**, **Thought for …**) and the tools it called (**Used N tools**). **Copy message** copies an answer.

A table in an answer has **Open spreadsheet**. It opens the table in a panel beside the conversation, where you can edit cells, copy the table and download it with **Download CSV** or **Download Excel**.

### The floating assistant

The **Volt AI** button in the dashboard header, the whiteboard editor and the canvas toolbar opens the same chat in a floating panel, with **New conversation** and **Open full AI page**. When you leave the AI page with a conversation open, the floating panel picks it up.

### How a turn runs

- A conversation runs one turn at a time. Sending while VOLT AI is still answering is refused.
- The turn runs on the server. Closing or reloading the tab does not stop it, and a tab that opens the conversation mid-turn sees what has been said so far. Only **Stop generating** ends a turn early.
- A turn takes at most 48 model steps.
- When a conversation grows long (about 240,000 characters of history), VOLT folds its earlier part into a summary that the model reads instead. The model can also fold it on demand with the `context_compact` tool.

## Tools

VOLT AI works through tools. Server tools run on the VOLT server with your identity, in the conversation's team. Browser tools run in your tab: they navigate, open panels and control the 3D viewer. A browser tool runs only in the tab that sent the message. With no such tab, nothing runs and the model is told so. Viewer tools wait up to 30 seconds for the viewer to open before reporting that none is open.

### Permissions

VOLT AI uses your role in the team, never more. Each tool declares the team permission that the same operation needs over the HTTP API. The model is offered only the tools your role allows; it does not see the others. Tools marked `—` below touch only your own account or screen, or need only team membership, as their HTTP twins do.

Using VOLT AI itself needs:

| To | Permission |
|---|---|
| Open the AI page and your conversations | `ai-conversation:read` |
| Send messages, and approve or reject cards | `ai-conversation:create` |
| Rename / delete a conversation | `ai-conversation:update` / `ai-conversation:delete` |
| Load the team's providers and models | `team:read` |

With the built-in roles, **Owner** and **Member** can use VOLT AI. **Viewer** cannot. **Admin** has every `ai-conversation` permission but not `team:read`, so the AI page cannot load the team's providers for an Admin.

### Approvals

A tool that changes your work asks you first. Instead of running it, VOLT AI shows a card with what it wants to do and the input it will use, with **Approve** and **Reject** (or **Approve all N** and **Reject all** when it asks for several at once).

- **Approve:** the server runs the tool with exactly the input on the card, after checking your permissions again. The card shows **Approved. Running…**, then the result, or **Approved, but it failed: …**.
- **Reject:** nothing runs. The card shows **Rejected. Nothing ran.** and VOLT AI asks what you would rather do.

While a card is waiting, the model cannot call that tool again; it answers your other questions instead.

Every tool that writes asks first, with these exceptions, which run without a card: `update_conversation` (rename this conversation), `create_scripting_notebook`, `create_whiteboard`, `clone_plugin` (makes a new draft) and `draw_on_whiteboard`. `manage_sessions` asks first to revoke sessions, but not to list them. Tools that only read never ask. Neither do the browser tools that only change what your screen shows.
